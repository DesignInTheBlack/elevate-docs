---
title: "Envelopes"
description: Condense a utility list into a single class and reopen it later.
---

An envelope turns a long class list into one named class, like `env:card`, that you can reuse anywhere and reopen to edit. Elevate keeps the class lists in `elevate.env.json` at your project root and rewrites your file for you when you save.

## Create an envelope

Add `env:name` alongside your utilities. On save, Elevate captures the utilities and condenses the class list to just `env:name`.

```html
<div class="env:card pd-x:d4 bg-color:red mg-t:d1 @hover:[bg-color:blue]">
  Env definition
</div>
```

After save, the class list becomes:

```html
<div class="env:card"></div>
```

## Open an envelope

To edit an envelope, use `env:name:open`. On save, Elevate expands the class list and keeps the `:open` marker so it stays open until you close it. While open, edits update the registry on save.

```html
<div class="env:card:open"></div>
```

Expands to:

```html
<div class="env:card:open pd-x:d4 bg-color:red mg-t:d1 @hover:[bg-color:blue]"></div>
```

## Close an envelope

Remove `:open` and save to condense back to a single class:

```html
<div class="env:card"></div>
```

## Envelope lifecycle (what changes in the file)

1. **Define**
   - You write `env:card` alongside utilities.
   - On save, Elevate records the utilities into `elevate.env.json` and rewrites the class list to only `env:card`.

2. **Open**
   - You change the class to `env:card:open`.
   - On save, Elevate expands the stored utilities into the class list and keeps `:open` so the envelope stays editable.
   - While open, every save updates the envelope registry with your edits.

3. **Close**
   - You remove `:open`.
   - On save, Elevate collapses the class list back to `env:card` and the registry keeps the latest version.

## Combined example

This shows breakpoints and states captured inside an envelope:

```html
<div class="env:card pd:d4 bg-color:indigo-3 text:white /sm/ pd:d6 /lg/ bg-color:indigo @hover:[bg-color:indigo-2_text:white]">
  Card
</div>
```

On save, this becomes:

```html
<div class="env:card"></div>
```

## Rules and notes

- Prefer one envelope per class list. Multiple env definitions skip auto-condense.
- Names use letters, numbers and dashes.
- Defining the same name twice with different classes stops the build with an Env Conflict. Reopen the envelope with `:open` to change it.
- Breakpoints and state blocks are captured as part of the envelope.
- Combinator directives are allowed; they target relatives of the env element (implicit env scope).
- Auto rewrite only runs on static class strings. Dynamic className expressions are skipped.
- `env:open` expansion only runs when the class list contains only env tokens (plus optional ctx or breakpoint markers).
