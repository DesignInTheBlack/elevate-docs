---
title: "Scopes and specificity"
description: "How ctx scopes make a component's classes stronger and keep them to that component."
---

Every Elevate class is a single class selector, so they all carry the same weight, and an outside stylesheet can override them. A scope fixes that for one component: classes inside it compile with the scope's class in front, which makes them stronger and keeps them to that component.

## Open and close a scope

| Marker | What it does |
|---|---|
| `ctx:name` | Opens a scope called `name` |
| `ctx:end:name` | Closes the scope called `name` |
| `ctx:end` | Closes the most recently opened scope |

Put `ctx:name` on the component's outer element, and `ctx:end:name` on the last element that belongs to it. Scopes follow the order of class lists in the file, not the HTML nesting, so everything written between the two markers is in the scope. Name the scope after the component. Naming the end marker catches mistakes: Elevate warns if `ctx:end:name` doesn't match the scope that's open, or if a scope is never closed.

```html title="Card.astro"
<div class="ctx:card pd:d4">
  <h2 class="font:h5 ctx:end:card">Title</h2>
</div>
<p class="font:h5">Outside the card</p>
```

```css title="What Elevate writes"
.font\:h5 {
  font-size: 1.5rem;
}
.ctx\:card.font\:h5, .ctx\:card .font\:h5 {
  font-size: 1.5rem;
}
.ctx\:card.pd\:d4, .ctx\:card .pd\:d4 {
  padding: 1rem; /* written as four sides */
}
```

Inside the card, `font:h5` matches through `.ctx\:card`, with two classes of specificity. Outside it, the plain one-class rule applies.

## Scopes and relational selectors

Combinator directives such as `@child:[…]` and `@siblings:[…]` style elements relative to a boundary, so they need an open scope. See [States and selectors](/reference/supported-selectors/). Inside an [envelope](/guides/4-env-aliases/), the envelope's own element is the boundary, so no `ctx:` is needed.
