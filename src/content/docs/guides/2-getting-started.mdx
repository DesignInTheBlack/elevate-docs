## Install

Elevate needs Node.js 18 or later.

<Steps>

1. Add Elevate to your project.

   ```bash
   npm install elevate-framework
   ```

2. Set it up. This copies an `elevate/` folder into your project and adds an `elevate` script to your `package.json`.

   ```bash
   npx elevate-framework prepare
   ```

3. Start the compiler. It watches your files and rewrites `elevate.css` every time you save.

   ```bash
   npm run elevate
   ```

4. Link `elevate.css` in your page, and start writing classes.

</Steps>

By default Elevate watches `elevate/templates` and writes `elevate.css` to your project root. Point it at your own source folder in [Configuration](/guides/3-configuration/).

## How a class is built

Every class names a property, then one or more values, separated by colons.

```html
<p class="text:grey-2">…</p>
```

Some properties stand on their own, like `block` (`display: block`) or `relative` (`position: relative`).

Most take values, and one class can carry several:

```html
<p class="text:grey-2:snug:left">…</p>
```

```css title="What Elevate writes"
.text\:grey-2\:snug\:left {
  color: #25262A;
  line-height: 1.3;
  text-align: left;
}
```

Elevate works out which value is which, so order doesn't matter: `text:left:snug:grey-2` compiles to the same declarations. The one exception is spacing. In `pd:d6:d3` or `mg:d2:d4:d4:d8`, position decides the side. See [Margin and padding](/css/marginpadding/).

Every value is checked against your design tokens. A value that isn't in the system, like `pd:d99`, stops the build and names the file and line. Try it in the [playground](/playground/).

## Responsive classes

Elevate is mobile-first. Classes at the start of the list apply at every width. A breakpoint marker like `/md/` means "from this width up", and applies to every class after it until the next marker.

```html
<div class="col gap:d3 pd:d4 /md/ row gap:d6 /lg/ pd:d8">…</div>
```

This is a column on phones, a row from `md` (768px) up, with more padding from `lg` (1024px) up. The [breakpoints](/default/breakpoints/) page lists every width.

## States

A state block applies a group of classes only in a certain state. Join the classes with `_` so the block stays one class.

```html
<button class="bg-color:grey+4 @hover:[bg-color:indigo_text:white]">Continue</button>
```

Chain states with `+`, for example `@hover+focus-visible:[…]`. [States and selectors](/reference/supported-selectors/) covers pseudo-elements and styling related elements.

## Plain CSS classes

Elevate checks every class in the attribute. To keep a regular class next to Elevate's, start it with a dash, or list it in `SafeList` in `elevate/config/elevate.ts`. Either way, Elevate leaves it alone.

```html
<div class="-js-menu row gap:d4">…</div>
```

## Putting it together

Write the classes in this order, and a long list stays easy to read:

1. `ctx:` scopes, if any
2. Classes for every width, including states
3. Each `/breakpoint/`, followed by what changes there

```html
<article class="col gap:d3 pd:d4 bg-color:white bd:round-d4 @hover:[shadow:soft] /md/ row pd:d6">…</article>
```

To reuse a list like this, turn it into an [envelope](/guides/4-env-aliases/).

## The parts of Elevate

Three kinds of files decide what a class can say. You'll usually only touch them to add your own brand.

| Part | What it holds | Where |
|---|---|---|
| Design tokens | The values: colors, spacing, type, effects | `elevate/design/`, registered in `elevate/config/design.ts` |
| Rules | Prefixes and value lists, like `fill-` for a brand color | `elevate/rules/`, registered in `elevate/config/syntax.ts` |
| Properties | Which CSS each property writes | `relationships` in `elevate/config/syntax.ts` |

[Configuration](/guides/3-configuration/) walks through adding a custom `brand` property that compiles `brand:fill-popgreen:copy-popwhite`.

## Running Elevate in its own process

If your framework's dependencies clash with Elevate's, as can happen with Next.js, give the `elevate/` folder its own `package.json` and run it from there:

```json title="elevate/package.json"
{
  "type": "module",
  "scripts": {
    "start": "NODE_PATH=../node_modules tsx core/index.ts"
  }
}
```

On Windows, use `set NODE_PATH=../node_modules && tsx core/index.ts`. Elevate resolves `Watch` and `Output` from the folder it runs in, so update those paths in `elevate/config/elevate.ts` to point back at your project, for example `../src`.
